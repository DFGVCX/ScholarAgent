# v4 Chunk Embedding 上下文策略

`scholar_hierarchical_v4` 将返回原文 `content` 与用于向量化的文本分开。每个 Chunk 的 `chunk_metadata.embedding_context_policy` 记录策略版本和实际使用的上下文模式，便于重建和回归。

当前策略版本为 `v1`：

| Chunk | 论文标题 | 章节路径 | 额外上下文 |
| --- | --- | --- | --- |
| 普通正文 | 否 | 是 | 仅 Chunk 原文 |
| 摘要、结论 | 是 | 是 | Chunk 原文；标题作为论文主题提示 |
| 公式 | 是 | 是 | 公式原文及同章节前后完整解释句 |
| 图片 | 是 | 是 | 图题、同章节局部上下文和正文中的显式引用句 |
| 表格 | 是 | 是 | 表题、表头、完整行分片和局部上下文 |
| 算法 | 是 | 是 | 算法编号/标题、输入输出、完整步骤分片和局部上下文 |
| 代码 | 是 | 是 | 代码原文与局部作用域上下文 |

这样做避免给每个普通正文 Chunk 无条件重复论文标题，减少上下文 Token 和同质化；对脱离论文后容易失去含义的结构对象仍保留论文级和章节级主题。策略只改变 `embedding_text`，不会改写前端展示、引用和调试使用的完整原文。

历史 `legacy_fixed`、`structure_aware_v1`、`formula_aware_v2` 和 `multimodal_aware_v3` 没有该策略元数据时，继续使用原来的“论文标题 + 章节路径 + 原文”格式，保证已有评测基线可复现。

首次入库和重新向量化共用同一个 embedding 文本构造函数。已经由旧版 v4 生成、但尚未保存 `embedding_context_policy` 的 Chunk 也会保持旧格式；要采用 `v1` 策略，需要对该论文重新执行 PDF 解析/切片，而不是只重建向量。这样不会在一次普通 reindex 中静默改变历史向量语义。
