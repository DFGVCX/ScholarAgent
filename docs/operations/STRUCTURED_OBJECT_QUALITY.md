# 结构化对象质量诊断

`scholar_hierarchical_v4` 会为公式、表格、图片、算法和代码 Chunk 保存一份版本化的自动诊断：

```json
{
  "version": "v1",
  "status": "usable | review | rejected",
  "score": 0.85,
  "reasons": ["low_extraction_confidence"],
  "checks": {}
}
```

该对象位于 `paper_chunks.chunk_metadata.object_quality`。同一 PDF 原子对象拆成多个 Chunk 时，各分片复制同一份对象级诊断，便于逐块追溯；完整 Chunk 原文不因诊断而截断或改写。

## 诊断内容

- 通用：正文是否存在、标题是否存在、PDF 坐标是否有效、结构化内容与原图是否可用、解析器置信度和上游质量原因。
- 公式：Markdown/LaTeX 是否可用，花括号、圆括号、方括号和 `$$` 分隔符是否平衡。
- 表格：是否为 Markdown 网格，是否具有表头分隔行，行数、列数和各行列数是否一致。
- 图片：图题或原图资产是否至少有一种可用于人工核查。
- 算法：步骤数以及 Input/Output 声明是否存在。
- 代码：是否有 Markdown 代码围栏、语言标签和代码行数。

`score` 是可解释规则的诊断分，不是论文内容正确率，也不替代人工标注、表格单元格准确率、公式符号准确率或图片裁剪 IoU。`review` 和 `rejected` 对象仍保留在切片与资产清单中，系统不会因自动诊断直接删除来源证据。

## 页面验收

重新解析论文后，进入“知识库 → 论文 → 切片”，选择公式、表格、图片、算法或代码。每个结构化 Chunk 的完整原文下方会出现“对象质量”，展开后可查看：

- 状态与诊断分；
- 上游和本层质量原因；
- 该类型的具体检查值。

旧内容版本没有 `object_quality` 时页面保持兼容，只是不显示诊断。要为已经入库的论文生成该字段，需要用 `scholar_hierarchical_v4` 重新解析和切片。

## 后续评测边界

这套诊断用于快速发现疑似坏对象并支持人工抽查。发布级质量仍需要独立评测集：公式符号/结构正确率、表格行列与单元格准确率、图片裁剪 IoU 与人工可用性、算法步骤完整率。自动诊断与检索 Recall@K、Precision@K 也应分别报告，不能相互替代。
